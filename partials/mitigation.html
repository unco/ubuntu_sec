Drop incoming IPv4 TCP packets with IPv4 header options (IP header length > 20 bytes) using your host firewall until a fixed kernel is installed.

Normal IPv4 TCP traffic, standard TCP options (timestamps, window scaling, SACK), UDP, and IPv6 keep working; only TCP connections that use IPv4 header options will fail.

  • Covers traffic to the host itself (including loopback), but containers or guests with separate network namespaces need the rule applied inside each namespace.
  • Blocks remote network attempts, but local processes can still set IPv4 socket options, so this reduces risk rather than replacing the kernel update.
Show how to apply and revert the mitigation

Apply the mitigation

Use only the section that matches your firewall.

UFW

Use when sudo ufw status shows Status: active.

  1. In /etc/ufw/before.rules, add this line right after # End required lines (above the loopback and RELATED,ESTABLISHED rules): 
    -A ufw-before-input -p tcp -m u32 --u32 "0>>24&0x0f=6:15" -j DROP
  2. Reload UFW. This also persists across reboots. 
    sudo ufw reload

iptables

Use when UFW is inactive and nftables is not managing rules (including Ubuntu 16.04, 18.04 and Ubuntu Core).

  1. Apply the rule immediately at the top of INPUT: 
    sudo iptables -I INPUT 1 -p tcp -m u32 --u32 "0>>24&0x0f=6:15" -j DROP
  2. Persist it across reboots:
    • Classic Ubuntu: save with iptables-persistent, or add the command to your firewall script. Installing iptables-persistent removes the ufw package. 
      sudo apt-get install iptables-persistent
sudo netfilter-persistent save
    • Ubuntu Core: run the command at startup from a snap daemon with the firewall-control interface connected, or per device with a oneshot unit in /etc/systemd/system.

nftables

Use when /etc/nftables.conf manages the firewall (without UFW).

  1. Create and load the rule now: 
    printf '%s\n' 'table inet cve_2026_98432 {
  chain input {
    type filter hook input priority -310; policy accept;
    ip protocol tcp ip hdrlength > 5 counter drop
  }
}' | sudo tee /etc/cve-2026-98432.nft >/dev/null

sudo nft -c -f /etc/cve-2026-98432.nft && \
  sudo nft -f /etc/cve-2026-98432.nft
  2. Persist it across reboots. Do not enable nftables.service if UFW is active, because the default /etc/nftables.conf flushes existing rules. 
    echo 'include "/etc/cve-2026-98432.nft"' | sudo tee -a /etc/nftables.conf

sudo nft -c -f /etc/nftables.conf && \
  sudo systemctl enable nftables.service

Revert the mitigation

After booting into a fixed kernel.

UFW

Delete the -A ufw-before-input ... 0>>24&0x0f=6:15 -j DROP line from /etc/ufw/before.rules, then reload:

sudo ufw reload

iptables

Remove the live rule, and any startup hook or snap rule you added:

sudo iptables -D INPUT -p tcp -m u32 --u32 "0>>24&0x0f=6:15" -j DROP

If you saved it with iptables-persistent, update the saved rules:

sudo netfilter-persistent save

nftables

Remove the boot include, the rule file and the live table:

sudo sed -i '\|^include "/etc/cve-2026-98432.nft"$|d' /etc/nftables.conf
sudo rm -f /etc/cve-2026-98432.nft
sudo nft delete table inet cve_2026_98432
